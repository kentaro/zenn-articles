米TypeSafe AIのJevは、文章を生成せず、あらかじめ渡した選択肢それぞれの確率だけを返すモデルです。2026年9月18日から[ロリポップ！AIゲートウェイ](https://lolipop.jp/ai/gateway/info/product/2026-09-18/)経由で使えるようになり、9月24日までは無料で試せます。

分類や振り分けのためのモデルですが、選択肢を「その局面で指せる手」にすれば、将棋の指し手も選ばせられます。そこで、Jevに将棋を指させ、手元で動かした将棋エンジンと対局させました。判断はすべてJevに任せ、探索エンジンは使っていません。

[コードと棋譜、対局の動画はGitHubに置いています。](https://github.com/kentaro/jev-shogi)

## Jevの呼び出し方

JevのAPIには、評価対象の`state`と、名前を付けた質問の集まりを送ります。質問には、yes/noの確率を返す`noul`、候補の中から1つを選ぶ`choice`、段階評価を返す`score`の3種類があります。ロリポップ！AIゲートウェイでは、`POST /v1/systemone`に次のように送ります。

```json
{
  "model": "typesafe/jev-latest",
  "state": "商品が届きません。明日までに必要です。",
  "questions": {
    "urgent": {"type": "noul", "instructions": "至急対応が必要ですか？"},
    "department": {
      "type": "choice",
      "instructions": "どの担当に回すべきですか？",
      "criteria": {"delivery": "配送に関する問い合わせ", "other": null}
    }
  }
}
```

`choice`を指定すると、候補ごとの確率と、確率がもっとも高い候補が返ります。複数の質問を1回のリクエストにまとめて送れて、まとめても応答時間はあまり延びません。自宅の回線から計測したところ、短い文章に対して質問1問でp50が615ms、100問をまとめても802msでした。

## 将棋の指し手をchoiceとして聞く

盤面を`state`に入れ、その局面の合法手すべてを`choice`の候補にしました。候補の数は序盤で30前後、持ち駒が増えると百を超え、今回の対局では最大280手ありました。Jevの`choice`は候補255個まで受け付けるので、ほとんどの局面では合法手をそのまま全部渡せます。255を超えたときだけ、駒を取る手や王手を優先して255手に絞りました。

ただし、指し手の記号（「７六歩」など）だけを渡すと、その手で何が起きるかをJevは盤面から読み取らなければなりません。そこで、各候補に1〜2手先の事実を説明として付けました。次のような文です。

```
２二角成(88)。相手の角を取る（駒得+8）、成る、動かした馬はタダで取られる（駒損-12）
```

最終的に付けた事実は、取る駒、成るかどうか、王手か詰みか、動かした駒がタダで取られるか、ほかの駒が浮くか、指した後に相手に1手詰みがあるか、直前の自分の手を戻す往復の手か、の7種類です（最初の版では取る駒と王手の2種類だけでした）。どれもルールから機械的に数えられることで、どの手が良いかという判断は含めていません。判断を含めてしまうと、Jevではなくコードの実力を測ることになるからです。

同じリクエストで、現在の形勢（5段階の`score`）と、自玉が数手以内に詰まされる危険（`noul`）も聞きました。これは指し手の選択には使わず、記録と動画の表示に使っています。

## 相手と強さの目安

対局相手は、手元で動かした[Fairy-Stockfish](https://github.com/fairy-stockfish/Fairy-Stockfish)です。1手0.1秒で指させ、`Skill_Level`を−20から20まで5段階に変えて、弱い順に「最弱」「弱」「中」「強」「最強」と呼ぶことにしました。Jevは常に先手です。

`Skill_Level`は、エンジンがわざと悪い手を混ぜる度合いの設定で、将棋の段級位との対応はわかりません。そこで、強さの目安として、各局で相手が指した手のうち、最強設定（1手1秒）のエンジンが同じ局面で選ぶ手と一致した割合を数えました。最弱が9%（35手中3手）、弱が14%（37手中5手）、中が33%（27手中9手）、強が38%（29手中11手）、最強が50%（16手中8手）でした。

## 1回の判断で指させた結果

最初は、事実として取る駒と王手だけを付け、1回のリクエストで指し手を決めさせました。最強設定（この対局だけ1手1秒）と指させたところ、42手で詰まされました。

棋譜を見ると、Jevは飛車を２八から４八に動かした後、３八と４八のあいだを5回行き来しています。そのあいだに相手は８筋から攻め、Jevの陣を破りました。候補の説明から見える範囲では、飛車の往復は駒も取られず王手もかからない無難な手なので、Jevはそれを選び続けたと考えられます。

## 候補を絞ってから比べる

そこで、候補の事実を上の7種類に増やし、判断を2段階にしました。1回目のリクエストで全合法手から上位6手に絞り、2回目のリクエストでは6手それぞれを指した後の局面を並べて、どれが最善かを選ばせます。1手につき2リクエストです。

この形で5段階の相手と1局ずつ指させた結果が次の表です。

| 相手 | 結果 | Jevの判断時間（p50） | 入力トークン |
|---|---|---|---|
| 最弱 | 71手でJevの勝ち（詰み） | 1,466ms | 221,841 |
| 弱 | 75手でJevの勝ち（詰み） | 3,130ms | 270,992 |
| 中 | 54手で負け（詰み） | 3,058ms | 128,412 |
| 強 | 58手で負け（詰み） | 3,297ms | 145,492 |
| 最強 | 32手で負け（詰み） | 4,163ms | 78,114 |

判断時間は1手あたり2リクエストの合計です。最弱との対局だけを単独で回し、残りの4局は同時に回しました。

最弱と弱には、最後まで詰ませて勝っています。5局でJevが指した146手のうち、候補の説明に「タダで取られる」と書かれた手を選んだのは2手でした。一方で、負けた3局はどれも同じ形でした。玉を囲わないまま攻められ、玉が盤の中ほどや端へ逃げ出して、最後は駒を取る手や歩1枚で詰まされています。駒の損得は説明に書かれていても、玉の安全は書かれていないので、Jevはそれを判断に入れられていません。

## 相手の応手を読ませる

さらに、Jev自身に先を読ませる形を2つ試しました。どちらも、読みの一手一手と局面の評価をJevに任せ、コードは事実を数えるだけです。事実には、玉の周りの味方の駒の数、玉の周りへの相手の利きの数、盤上と持ち駒を点数にした駒割（歩1、香3、桂4、銀5、金6、角8、飛10）を足しました。

1つ目は、上位6手それぞれについて、相手の最善の応手をJevに選ばせ、応手の後の局面をJevに評価させる形です（1手3リクエスト）。2つ目は、読みと評価を分け、6本の手順をそれぞれ3手先（相手、自分、相手）までJevに指し進めさせてから、読み切った局面の形勢だけをJevに評価させる形です（1手5リクエスト）。各手順の読みは、6本分を1リクエストにまとめて聞いています。

| 相手 | 2段階 | 応手を読む（3リクエスト） | 3手読んでから評価（5リクエスト） |
|---|---|---|---|
| 中 | 54手で負け | 54手で負け | 80手で負け |
| 強 | 58手で負け | 66手で負け | 28手で負け |
| 最強 | 32手で負け | 46手で負け | 48手で負け |

どの形でも、中以上には勝てませんでした。中との対局では3手読む形が80手まで粘りましたが、強との対局では逆に28手で負けています。

記録を数えると、Jevが読みの中で予想した相手の応手が、実際に相手が指した手と一致したのは、応手を読む形で68手中10手、3手読む形で70手中12手でした。読みの中で相手の手を外していると、読み切った局面は実際には現れない局面になり、それを評価しても指し手の良し悪しを測れません。候補の説明に書かれた駒の損得には従えても、相手の狙いや盤面全体の形勢を捉える判断までは届かない、というのが今回の結果です。

## 速さと費用

1局だけを回したときの判断時間は、2段階の形で1手p50 1,466msでした。1回のリクエストで指した最初の対局では、p50 677msです。約30の候補手を渡して、1秒かからずに確率が返ってきます。

費用は入力トークンだけに課金され、出力は無料です。2段階の形の5局で入力は合計約84万トークン、通常の単価（入力100万トークンあたり$0.042）で約$0.035でした。3手読む形は1手あたりの入力が大きく、最強との1局（Jevが24手指した）で約83万トークン・約$0.035、中との1局（Jevが40手指した）で約191万トークン・約$0.080でした。

## Jevに将棋を指させてわかったこと

Jevは、合法手すべてを選択肢として渡せば将棋を指せます。1〜2手先の事実を候補の説明に付けると、手加減の大きい相手には詰ませて勝てました。一方で、玉の安全や形勢のような盤面全体の判断は弱く、Jevに先を読ませても中以上の相手には勝てませんでした。

将棋は判定特化モデルの用途としては無理のある題材です。それでも、候補を255個まで一度に渡せて、確率がそのまま返ってくるので、「ルールで候補を列挙し、選ぶ判断だけをモデルに任せる」という組み方は試しやすく感じました。問い合わせの振り分けや投稿のチェックのように、候補と判断材料を文章で渡せる処理でも、同じ組み方で試せます。
